## Ce que les faux négatifs ne justifient pas

Les messages complets de commits contiennent déjà list/run, la consigne dropped_parameters, les limites Swift/Agent, le changement du watcher et le problème eval/out. Les chemins React, le tag de palier et les codes lint/build/deploy sont également dans les commandes. Aucune de ces omissions candidates ne nécessite des embeddings, du réseau, une capture de contenus ou un transcript plus volumineux.

Une relation « fichier modifié → commit » reste insuffisante pour affirmer que ce fichier est propre. Des écritures SQLite après une commande migrate échouée ne prouvent pas que la migration a fini par réussir. Un meilleur modèle peut expliquer cette incertitude ; aucune collecte proposée ne doit être vendue comme une preuve universelle d’état actuel.

Le stockage ne peut pas être chiffré honnêtement en Mo/jour avec ce corpus : il ne contient pas les sorties que l’on propose éventuellement de capturer. Pour un futur essai limité, mesurer `nombre d’événements concernés × octets réellement conservés`, après masquage, puis juger le gain utilisateur face à ce coût. Aucun benchmark ou quota arbitraire n’est créé ici.
